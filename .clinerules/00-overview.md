# プロダクト概要（全バージョン共通）

このディレクトリ（`.clinerules`）の各ファイルは、実装フェーズ（`init` / `v0` / `v1` / `v2` / `v3`）ごとに仕様を分割したものです。
実装作業を行う際は、対象フェーズのファイルと本ファイル（共通仕様・共通ルール）を必ず参照してください。

## ペルソナ

- **おじ**：80歳、男性、退職済み。配偶者が施設に入居しており孤独を感じている。都会在住。テレビをずっと見ている。足が悪くあまり動けない。スマホは持っているがあまり使わない。
- **孫**：10代〜20代。学校がある。スマホを持っている。

## 課題

- コミュニティの希薄化、配偶者との隔離による孤独
- 話さない（話したいけど話せない、話せる機会があっても話さない）
- ぼける（散歩・運動をしない）、健康

→ これらを解消できるアプリを作りたい。

## アプリの目的とタイトル

- **目的**：上記の課題、特に**孤立感の解消**が目的。
- **タイトル**：死期が近いおじい向けBeReal的アプリの最小実装。

## アプリの概要

- **コンセプト**：おじいを死なせない（ゲージを切らせない）。リアクションがないと死期ゲージが減っていく。
- **登場人物**：
  - 孫：写真撮影もしくはギャラリー連携で写真を共有する。
  - おじい：一日一回送られる写真にリアクションをとる（＝安否確認）。

## アプリの仕様（共通の考え方）

- 写真を送信したとき、通知が表示される。
- おじいちゃんはリアクションしないと、アイコン的なものが薄くなっていく。
- 認知症とも絡めて、毎日一回行う想定。
- おおよその年齢で死期を設定し、リアクションしたら伸びる想定。
- 育成ゲーム的な要素（たまごっち的な育成の楽しさ）を持たせる。
  - リアクションをしないとゲージが減る。
  - アプリ上で「死ぬ」とリアルでは生きているがおじいちゃんは死ぬ（という表現）。
  - エンドロールで走馬灯（画像）が流れる想定。
- ギャラリー連携を想定（おじいちゃんが映った写真を想定）。
- リアルタイムで撮影した写真・動画だとゲージ上昇量が大きくなる想定。

## 画面遷移

### 孫側

- 死期表示画面
- カレンダー
- カメラ

### おじいちゃん側（2タブ想定）

- 死期表示画面（アイコン（おじいちゃんの顔など）を死期が近づくにつれ薄くする、死期が伸びると精神面にも良い効果を期待）
- 写真にいいねをする画面
- アルバムをカレンダー表示する画面

**おじいちゃんがすること**

- 孫からの写真にいいねをする（システム側：ランダム通知、送信、クラウド側にストックしているものを収集）
- この写真でいいかをOKすること

## 技術要件

- **アプリ形態**：ネイティブアプリ（スマホ想定）

### フロントエンド

- React Native (Expo)
- TypeScript

### バックエンド

- Supabase
  - リージョン: Northeast Asia (Tokyo)
  - DB: Supabase Database (PostgreSQL)
  - Storage: Supabase Storage
  - API: PostgREST（`@supabase/supabase-js` からテーブルへ直接アクセス）／必要に応じて Database Functions (RPC)
  - 認可: RLS（Row Level Security）
  - 通知: Expo Push Notifications ＋ Supabase Edge Functions

## 実装上の共通ルール

- 仕様書（`.clinerules` 配下の各mdファイル）に書かれていること以外は実装しない。
- 実装する前に、どのファイルを変更するのかを必ず確認すること。
- build不要とする。実機確認は行わない。Webでの確認も不要。
