# v0 フェーズ

> 前提として `00-overview.md` の共通仕様・共通ルールを必ず参照すること。

## このフェーズでやること

- 孫が写真をアップロードする（Supabase Storage に保存）
- おじいがリアクションボタンを押す
- 使用するSupabase機能は **Storage, Database (PostgreSQL), RLS**（通知などはこのフェーズでは未使用）
  - モバイルアプリ（Expo）から `@supabase/supabase-js` を用いて Supabase へ直接アクセスする。API サーバーは設けない。
    - **Storage**：写真の実体を `photos` バケットに保存する。クライアントから直接アップロードし、公開URLを `photos.image_url` に記録する。
    - **Database**：`group` / `users` / `photos` / `reactions` テーブルへ PostgREST 経由で読み書きする。
    - **RLS**：クライアントには `anon` キー（公開鍵）のみを配布し、テーブルへのアクセス範囲は RLS ポリシーで制御する。`service_role` キーはアプリに埋め込まない。

## データベース設計（RDB）

```
group {
  id
  name?
  users
}

users {
  id
  group_id
  name
  role      // child | uncle
  created_at
}

photos {
  id
  group_id
  uploader_id
  image_url
  created_at
}

reactions {
  id
  photo_id
  reactor_id
  created_at
}
```

## 画面構成

- **共通**：group_id を入力・表示する
- **孫側**：写真アップロードボタン
- **叔父側**：上部に写真、下部にボタン

## 実装上の注意

- このフェーズで実装するのは上記の画面構成・DB設計・機能のみ。
  - 寿命ゲージ、リアクション時の制限時間撮影、エンドロール、通知などは v1 以降のスコープであり、v0 では実装しない。
- 仕様書に書かれていること以外は実装しない。
- 実装する前に、どのファイルを変更するのかを必ず確認すること。
- 動作確認は `build` のみとする。実機確認は行わない。Webでの確認も不要。
